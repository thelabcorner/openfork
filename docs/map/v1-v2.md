# V1 vs V2/current

“V1” and “V2” are overloaded terms in this repository. Treat them as separate axes.

## Axis 1: execution/domain generation

This is the architectural distinction that matters most.

| | Legacy / V1 | Current / V2 |
| --- | --- | --- |
| Primary runtime owner | `packages/opencode` | `packages/core` |
| Session execution | `src/session/prompt.ts`, `processor.ts`, related V1 session modules | `src/session/runner/*`, `execution/*`, input/event/projector services |
| Tool registry | `packages/opencode/src/tool/registry.ts` and V1 tool tree | `packages/core/src/tool/registry.ts`, `builtins.ts`, current tool services |
| Persistence model | legacy-compatible session/message structures plus shared Core persistence seams | durable Core domain rows/events, admitted session input, projectors |
| Architectural role | production compatibility and mature execution surface | convergence target / current domain model |

V1 is still production code. The migration rule is not “delete V1 whenever a V2 file
exists”; it is “make V1 compatibility converge toward the current semantic model
without breaking mature behavior.”

Examples of semantics that must converge across generations include:

- turn provenance and ownership;
- instruction authority vs provider role;
- Goal lifecycle and continuation behavior;
- session/tool lifecycle state;
- event and projection semantics;
- shared provider/tool protocol behavior where applicable.

## Axis 2: HTTP/API generation

API naming does **not** map cleanly onto runtime generation.

`packages/app/V1_API_MIGRATION.md` explicitly defines its “V1 API” as the legacy
unprefixed HTTP endpoints, even though many of those calls are exposed through a
package named `@opencode-ai/sdk/v2`.

Practical rule:

- legacy unprefixed endpoints such as historical `/session`, `/global`, etc. are
  migration/compatibility surface;
- current Protocol endpoints live under the current `/api/*` contracts;
- the full `OpenCodeHttpApi` composes both current Protocol APIs and OpenCode-owned
  local runtime routes;
- `@opencode-ai/sdk/v2` is a generated-client namespace, **not proof that a call is
  using the current/V2 execution runtime**.

## Axis 3: UI generation

Folders and components named `v2` under `packages/app` or `packages/session-ui`
usually identify a newer presentation/component generation.

Examples:

- `packages/app/src/pages/session/v2/*`
- `packages/app/src/components/settings-v2/*`
- `packages/session-ui/src/v2/*`

These names do not by themselves answer:

- which HTTP endpoint is called;
- which generated client is used;
- whether execution runs through V1 or Core/current;
- who owns the underlying domain state.

The root `AGENTS.md` states this directly: a “V2” suffix in a UI component is not an
API-version decision.

## Hybrid seams

The important shared/transition seams are:

- `packages/opencode/src/server/routes/instance/httpapi/*` — one full local API host;
- `packages/opencode/src/session/message-v2.ts` — a compatibility/current seam
  inside the legacy host package;
- `packages/core/src/v1/*` — centralized V1 compatibility logic that belongs in
  Core rather than being reimplemented by every consumer;
- `packages/app/src/context/server-sdk.tsx` — client-side compatibility/current
  transport composition;
- `packages/schema` — browser-safe shared contracts;
- `packages/llm` — provider wire/protocol behavior shared below execution hosts.

## Direction of travel

```text
feature-specific V1 heuristics
          X
          |
          v
centralized compatibility boundary
          |
          v
current Core semantic model
```

New cross-generation behavior should normally be designed in the lowest shared
semantic owner first, then adapted into V1 where needed. Avoid creating a third model
in the UI or one-off legacy route handler.

## Review checklist

When you encounter “V1” or “V2”, identify which axis is meant:

1. execution/domain runtime;
2. HTTP/API surface;
3. generated-client namespace;
4. UI component generation;
5. schema/message compatibility.

If a design argument relies only on a `v2` pathname or SDK import suffix, it has not
established the architectural boundary.
