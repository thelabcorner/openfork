# OpenFork web tools: research, architecture and implementation ledger
Date: 2026-10-07
Status: actively researched and partially implemented; NOT a production closeout
Scope: OpenFork V1-first execution runtime, unified `web` tool; upstream OpenCode, OpenChamber, Oh My Pi (OMP), and free search APIs.

## Goal
Make external discovery a reliable, low-latency, low-context-cost default ability for all OpenFork agents rather than a provider-dependent special case. Reuse upstream mechanics and known algorithms, but preserve OpenFork's independent product identity, tiered ownership, current lazy-tool contract, and V1 production path. Source and test evidence outrank this ledger. The shared worktree has substantial concurrent changes: never reset/stash/clean/restore unrelated files.

## Findings verified against live code
- `packages/opencode/src/tool/web.ts`: the model-facing `web` wraps `webfetch` + `websearch`; `url` alone selects fetch, `query` alone selects search. It delegates hooks and metadata. Previous model-facing copy disproportionately emphasized FETCH FIRST even when no URL existed. Its copy now explicitly encourages search for research/current facts and fetch for already-known URLs.
- `packages/opencode/src/tool/registry.ts`: `tool.web` is in the V1 built-in registry (currently lines ~430 and ~494). An older `webSearchEnabled` helper remains in source and tests but has no observed call site; don't mistake it for an active provider gate.
- `packages/opencode/src/tool/websearch.ts`: eight adapters (Parallel, Exa, Firecrawl, SearXNG, Brave, Tavily, Ollama and DuckDuckGo); Ollama is added as a credential-gated REST adapter for its official free account quota, not anonymous scraping. Automatic ordered fallback, preference flags, strict explicit pins. No second model-facing search tool. Failure and empty responses advance the chain. In-flight transport has per-candidate 12s and whole-search 45s deadlines; pinned provider has 25s; cancellation is propagated as cancellation rather than provider failure. The helper rejects plain 'No results found' prose.
- `packages/opencode/src/tool/mcp-websearch.ts`: previous MCP JSON-RPC parser returned just the first text block and ignored JSON-RPC errors and `result.isError`. Revised parser joins text blocks, recognizes remote errors, ignores non-text blocks.
- `packages/opencode/src/tool/websearch-shared.ts` and provider-specific adapters: REST responses now share a bounded Markdown result renderer (HTTP(S) URL check, credential URL rejection, URL deduplication, per-title/snippet/date/URL limits, 20-result maximum); Firecrawl's previously duplicate renderer now reuses it. Concurrent changes route providers through `readSearchResponseText` with a 5MiB streaming cap, rather than unbounded `response.text`.
- `packages/opencode/src/tool/webfetch.ts`: supports HTML -> Markdown/text conversion, attachment images and format negotiation. Current concurrent changes also use the bounded streaming response collector before materializing the 5MiB body. URL requests are still arbitrary http(s) inputs; SSRF/redirect-hop protections should be verified before widening network reach.
- `packages/core/src/tool/http-body.ts` is now a shared byte-bounded streaming collector; this addresses an earlier memory-allocation finding. Inspect cross-package ownership and test the exact cap/chunk boundary/abort cases before declaring production closure. Wall deadlines and streaming byte limits solve different problems.
- Firecrawl: keyless search was implemented in 2026; OMP explicitly supports it. Verified here by a *real anonymous POST* to `https://api.firecrawl.dev/v2/search`: HTTP 403 with explicit 'IP address looks suspicious ... cannot be used without API key from here'. This means keyless exists, but is *not* reliable for every IP. Keep it eligible, label it conditional, and the anonymous 401/403/429 cooldown is now implemented process-locally keyed by provider + auth mode (see the P2 record); a configured key bypasses the anonymous cooldown.
- Test evidence: existing web tests were green at baseline (37/37); a run during parser work surfaced outdated fallback expectations and an SSE fixture newline error, both corrected. The combined `bun test test/tool/websearch.test.ts test/tool/webfetch.test.ts` suite subsequently reported 45/45 green after adding Ollama request/parsing and REST normalization tests. After the P2 cooldown and renderer-boundary work it reported **55/55 pass, 0 fail, 249 expect() calls** (10 new tests: 7 cooldown, 2 typed-error/sanitization, 1 1200-candidate renderer flood; see the P2 record below). `bun run typecheck` on 2026-10-07 exited 2 with **22 errors total, 0 in web-tool files** (ACP/CLI/HTTP API/T3 compatibility/swarm/server-test files already under unrelated parallel work; a scoped tsgo check over `websearch.ts`, `firecrawl-websearch.ts` and `websearch.test.ts` also reported zero diagnostics in those files). This is NOT a repository-wide clean typecheck claim. `bunx oxlint` over those three files reports 0 warnings / 0 errors.
- Real host smoke check on 2026-10-07 with no API keys: Parallel MCP POST returned HTTP 200, JSON-RPC result and a provider-reported internal search cost of USD 0.001; Exa MCP POST returned HTTP 200 SSE with relevant documentation result; Firecrawl unauthenticated POST returned HTTP 403 with explicit IP anti-abuse message. These are three probes of one host at one instant, not a sustained availability/performance study. Ollama has only local mocked transport/response tests; no configured user key or authenticated live request was used.

## Upstream comparison
**OpenCode** `https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/tool/websearch.ts`: primarily Exa and Parallel MCP backends; session-ID checksum picks provider when not explicitly selected, no rich built-in cross-provider fallback in examined file. OpenFork already has a broader backend set and a better deterministic fallback policy; transplanting that implementation would regress useful work.

**OpenChamber** `https://github.com/openchamber/openchamber/blob/main/packages/web/server/lib/opencode/DOCUMENTATION.md`: its `websearch-config.js` exposes GET/PUT `/api/config/websearch` as a settings frontend/config writer for upstream OpenCode's chosen provider. It is NOT a new independent search engine. Useful lesson: expose effective provider config and project-file override precedence in settings. Do not copy its OpenCode-specific local config mutation contract verbatim: OpenFork is fork-owned.

**OMP / Oh My Pi** `https://github.com/can1357/oh-my-pi/blob/main/docs/tools/web_search.md`: `packages/coding-agent/src/web/search/` includes lazy provider registry, common `SearchResponse` with sources/citations/answer, parsed site/date/negative directives, explicit vs default candidates, abort propagation, a web role plus fallbacks, 23 provider adapters (including keyless Startpage/Google/Ecosia/Mojeek). `https://github.com/can1357/oh-my-pi` describes specialized source reading (GitHub, package registries, scientific papers, documentation). These are architecture/behavior donors, not a reason to copy 23 modules. OMP also has keyless Firecrawl with IP-conditional access. Its search response normalization, source metadata, bounded snippets and search directives are high-value independent ideas to port; its separate web-model role/whole provider catalog would be disproportionate without measured need.

## Proposed lowest-correct-owner design
1. **Model-facing `web`**: one compact dispatcher with optional `action`, `query`, `url` and advanced knobs; no dynamically repeated provider schema. Agents get short discoverability guidance. Expose provider introspection, not provider internals, only on request.
2. **Search coordinator**: single V1 shared owner for candidate selection, request-wide AbortSignal, search deadline, provider-specific hard cap, credential resolution, anti-abuse cooldown and structured attempt trace. Strict pins remain strict; automatic fallback is conditional on failure class; cancellation is terminal.
3. **Adapter contract**: `search(query, signal, params) -> { provider, sources:[{title,url,snippet,publishedAt?,fetchedAt?}], answer?, query?, warnings? }`; distinguish `unavailable/forbidden/auth/rate_limited/timeout/parse_error/empty/success`. Validate URL protocols and canonicalize/dedup before rendering. Tool output includes concise sources, not arbitrary upstream dumps. Preserve fallback provenance in metadata.
4. **Configuration**: read explicit user/workspace settings and secrets through their owning services. Distinguish *configured*, *keyless possible*, *host-verified*, *temporarily throttled*. Never output keys. Avoid per-session provider/network probes during tool enumeration; probes on execution or user-initiated diagnostic.
5. **Site-specific readers**: route known GitHub URLs to existing GitHub tool; experiment with npm/PyPI/MDN/docs/arXiv to improve retrieval via narrow readers, not broad browser auto-hydration.
6. **Transport/safety**: strict URL validation and redirect-hop policy, DNS resolution/IP block for metadata and RFC1918/internal destinations where appropriate; max bytes BEFORE allocating full payload; cap source/snippet count and length; forbid HTML search injection from overriding tool instructions; scrub key-bearing URLs and error details.
7. **Operations**: bounded per-process provider circuit state keyed by provider and auth-mode (not user query or session), TTL + half-open probe; 401/403 anonymous Firecrawl and 429 apply cooldown only to same mode; authenticated calls independent. Minimize retries; ensure persisted metrics exclude sensitive query text.
8. **Retrieval confidence**: source publication and fetch times separated; query filters `site:`, dates, `filetype:` should be truthful; never silently claim a provider honored an unsupported filter. Output should make it trivial for the agent to follow primary sources via `web({url})`.

## P2 implementation record: typed anonymous Firecrawl cooldown (2026-10-07)
Verified against the live tree after reconciliation; implementation and tests landed in the shared worktree (concurrent workers plus this campaign) and were confirmed by the run recorded above.

- `packages/opencode/src/tool/firecrawl-websearch.ts`: `HttpClient.filterStatusOk` rejections are wrapped by `Effect.mapError` into a typed `FirecrawlHttpStatusError { status: number; detail: string }` when the underlying error is a `StatusCodeError` (status extracted from the numeric `response.status`, 100-599; never regex-matched from message text). `sanitizeStatusDetail` strips control chars, redacts the configured `FIRECRAWL_API_KEY`, bearer tokens and key-shaped query values, and bounds the detail to 240 chars. Transport/decoding failures pass through unchanged. `isFirecrawlHttpStatusError` supports `instanceof` plus `_tag` matching.
- `packages/opencode/src/tool/websearch.ts`: process-local cooldown store keyed by `provider:auth-mode` (`anonymous`/`authenticated`). TTLs: 401 and 403 -> 5 minutes, 429 -> 1 minute; other statuses never record. `noteProviderCooldown` writes only in anonymous mode and never shortens a longer active window; `providerCooldownInfo` reads under the provider's *current* auth mode and deletes expired entries lazily (no timers, no persistence, no background probes, no eager provider requests). `searchWithFallback` records only from `Cause.findErrorOption` + `Option.isSome` on the typed error, skips cooldowned providers with an `unavailable` attempt (detail `cooldown Ns after HTTP <status>`), treats cancellation as terminal *before* recording (interrupted attempts record nothing), and bypasses the check when the strict pin (explicit `provider` param or `OPENCODE_WEBSEARCH_PROVIDER`) equals the candidate. A configured `FIRECRAWL_API_KEY` reads the separate authenticated bucket, so it bypasses by construction and an authenticated denial never pollutes the anonymous bucket.
- Introspection: `providerStatus`/`providersOutput` take an optional `now` (default `Date.now()`; the tool passes `Clock.currentTimeMillis`), appending `(cooldown Ns after HTTP <status>)` truthfully with zero network probes. The OXP/OFXP `providersOutput(flags)` call sites remain valid via the optional parameter. Model-facing `websearch.txt` documents the cooldown line and pin/credential bypass.
- Tests (`websearch.test.ts`, describe `websearch anonymous provider cooldown`, all fake-clock `TestClock` + fake HTTP, isolated env/cooldown state): TTL/auth-mode helper bounds including never-shorten and no-resurrect; first anonymous 403 -> second search `firecrawl:unavailable` with zero extra probes -> `TestClock.adjust("5 minutes")` expiry -> retry; 429 one-minute boundary (30s still skipped, 61s retried); configured-key bypass without clearing the anonymous bucket, key removal restores it; param pin and env pin bypass then fall back to skip; cancellation terminal with interrupt cause, no DuckDuckGo cascade, no cooldown recorded, later searches unaffected; providers introspection shows/hides/expires the cooldown with no network probe. Typed-error test asserts status 403, message content, no credential leak; a separate test pins `sanitizeStatusDetail` redaction and the 240-char bound; a 1200-candidate flood test pins the renderer boundary. Combined suite outcome: **55 pass / 0 fail / 249 asserts** (47 in `websearch.test.ts`, 8 in `webfetch.test.ts`).
- Not covered here (still open): P1 typed `SearchResponse` normalization contract, streaming-collector boundary tests, and P5 empirical benchmarks.

P3 next: truthy `providers` status and optional settings surface patterned on OpenChamber, config provenance and safe key enrollment. No costly workspace bootstrap for global introspection.
