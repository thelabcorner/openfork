# Renderer and Markdown worker priority implementation

Date: October 1, 2026. Scope: `packages/session-ui` Markdown rendering and worker admission. The shared app/server were not restarted or manipulated. No producer flush or timeline projection code was changed. This is implementation progress, not active-stream performance closure.

## Change

Before this change, parse, projection, and highlight each used a separate request transport with its own per-lane active slot. Those transports could each post one request to the same Worker, despite that Worker having one event loop. The worker also kept distinct parse/project/highlight queues. The renderer now has one host-side admission owner shared by all three work kinds and both worker lanes. Background and ordinary visible work use lane 0; selected visible-tail work uses reserved lane 1. Queue priority cannot preempt a parse already executing in a worker, so lane isolation is required for active-work latency.

`markdown-worker-admission.ts` enforces one in-flight request per lane across parse, projection, highlight, and key disposal. It coalesces queued requests by kind and key, so only the newest queued generation remains. Queued work is bounded to 128 jobs and 16 MiB total, with an 8 MiB per-job input cap. Background and ordinary visible work retain stable key affinity on lane 0; tail work is isolated on lane 1. The scheduler ranks work within a lane; waiting work ages upward, and a waiting non-tail job receives a turn after at most four tail admissions once priorities converge. The host tracks active/queued input bytes as well as counts.

One shared `IntersectionObserver` in `markdown-visibility.ts` owns viewport visibility for all rendered Markdown instances. Off-viewport work enters as background. Visible static/detail parsing is visible priority; visible streaming projection, parsing of the live tail, and code highlighting receive tail priority. A visibility change updates the resource source so queued obsolete-priority work can be superseded and resubmitted. General preloads default to background.

Disposal now goes through the same lane owner, broadcast to both lanes to clear worker-local state after a key migrates between lanes. The worker acknowledges disposal, then the lane is released. Cross-lane parse/project/highlight cache misses retry from retained full source; generation checks prevent stale responses from replacing newer host state. Traces add work priority, worker lane, and queue job/byte counts while preserving dispatch wait, worker queue wait, service time, and response wait.

The existing message pacing remains 24 ms. The retained artifacts contain no current active-stream display-latency baseline that would justify changing cadence, and producer-side flush changes are owned elsewhere in the campaign. Timeline projection and hydration code were not modified.

## Limits and next gate

The admission layer cannot preempt a synchronous lexer, Shiki call, or other task already executing. The 16 MiB bound limits each admitted input size and the two active lanes bound concurrent worker jobs, but actual CPU duration still depends on content and language initialization. Intersection visibility is viewport-based; it does not prove that a minimized or backgrounded Electron window is hidden from this signal. A hidden component's optional work is deprioritized rather than paused; provider/tool execution and persistence remain independent of presentation.

The next meaningful check is a real Electron renderer plus sidecar run with 1, 3, and 6+ active streams, long histories, and code-heavy content. Deliberately occupy both worker lanes with same-affinity parse/highlight work, then trigger a short selected visible-tail update. Capture priority, queue wait and bytes by lane and kind, provider-event-to-DOM-commit, stale/superseded work, renderer long tasks and frames, and confirm that cancellation/disposal drains without requiring tab navigation. Compare against a trace from the same build/workload before claiming latency improvement. Preserve the negative checks: one request in flight per lane across every work type; no metric-only history hydration; no obsolete queued generations dispatched; bounded queue/input bytes; and no presentation-visibility suppression of required session execution.

## October 2 cold-mount and hidden-window renderer repair (in progress)

The ownership path is durable message/part text -> production session sync store -> selected session timeline -> `MessagePart` -> `PacedMarkdown` -> `Markdown` -> shared projection/highlight workers -> sanitized block DOM. The server already owns the durable bytes; the Markdown renderer owns only the detail projection and presentation. Reverse demand starts at a mounted Markdown root and must be admitted by viewport, ancestor paint state, and document visibility before reading/escaping/checksumming the full body, creating a worker request, sanitizing HTML, or reconciling content. Session/tool execution, event consumption, and persistence do not follow this presentation gate.

Source inspection found a concrete initial-mount defect: the browser `createResource` initial value called `initialResult`, which could checksum the complete source, escape the entire source into one HTML string, and assign it to `innerHTML` before the observer knew whether the mounted row was visible. The native fixture already uses an opacity-zero in-viewport element, so intersection alone cannot establish paint demand. The previously measured 2.8–4.1 second LoAF/layout event therefore remained possible even with the reserved tail worker lane.

The current working-tree repair keeps the complete synchronous fallback only for SSR. A browser starts with an empty render result. A shared visibility owner gates worker/resource startup and DOM reconciliation using one IntersectionObserver, one MutationObserver, and one document `visibilitychange` listener. It tracks ancestor paint state (including opacity zero) and reuses computed ancestor facts once per observer/mutation delivery, avoiding repeated style reads for shared timeline ancestors. A cold hidden renderer mounts only a fixed bounded placeholder box; an already-rendered offscreen tree is retained. Hiding the document or a panel pauses optional projection/DOM commits; active server execution remains outside this code path.

Visible tails retain priority, but only the changing live/incomplete-code block receives the tail class; frozen completed blocks stay visible-history work. The non-background worker lane now accepts selected work as well as tails, while background work stays on lane 0. Completed bodies above 512 KiB first expose their complete raw text through a shared frame-paced text commit, bounded to 64 KiB / 128 nodes per frame; their rich worker conversion remains on the background lane so a single multi-megabyte completed parse cannot monopolize the lane used by live tails. Worker generation and DOM object guards reject stale commits, and cancellation removes pending writes when a renderer becomes hidden or is disposed.

The production Electron gate source has been extended to mount an 8 MiB-over-limit completed message inside an opacity-zero ancestor, assert zero worker events and no content block while hidden, require a measurable placeholder, then reveal the same root and require the trailing text marker, full output length, bounded commit bytes/nodes, and a maximum frame gap below 250 ms. That gate has **not** been run yet; it is held for root review. Session-UI typecheck passes; focused stream/projection/admission tests pass **44 tests / 203 expectations**; the private Vite port/cache isolation test passes **1 test / 8 expectations**.

The renderer now bounds the complete browser path rather than only the final DOM append. Completed projections are split at semantic top-level Markdown blocks; each worker parse input is capped at 512 KiB and batch materialization at eight blocks / 2 MiB. Rich HTML over 256 KiB falls back to complete source text. Sanitization is serialized by one shared frame owner; a byte/count reservation is acquired before worker HTML is materialized, so queue saturation waits on shared capacity instead of permanently degrading ordinary rich blocks. Reservations, sanitizer jobs, and waiters have explicit count and byte limits, owner cancellation, and bounded FIFO promotion.

DOM commits now use one shared scheduler for sanitized rich HTML, long prose, oversized plain code, and token-dense Shiki code. Text is retained as a source reference plus offset; every created text node is at most 16 KiB. Each animation frame is limited by 64 KiB of text, 128 nodes, 128 task steps, a 4 ms budget, and at most one 256 KiB template parse. Code tokens retain one span per token even when the token text crosses frame boundaries, and commits rotate fairly across jobs. Code copy reads the full block source while insertion is pending. Blocks above the token-object budget retain a pre/code/copy-control presentation and cooperatively commit their lossless inner code text. Hidden/disposed owners cancel pending commits and release host/worker parse state; visibility teardown rebuilds the shared ancestor observer once per microtask batch.

The isolated renderer gate now also checks oversized fenced-code structure, exact code-body length, full-source copy while the commit is pending, hidden-state zero worker jobs, frame limits, and teardown. Its Electron main entry configures a fixture-owned user-data/session-data/log/crash profile before `app.whenReady`; the test syntax-checks the built CommonJS entry and verifies the reported profile paths. This native gate remains held for root review and coordination; it has not been launched in this iteration.
