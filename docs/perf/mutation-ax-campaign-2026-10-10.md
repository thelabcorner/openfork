# OpenFork Mutation AX — Exact-Target Resolution Campaign

**Date:** 2026-10-10  
**Checkout:** `/webstormprojects/opencode`  
**State:** Source implementation and focused tests; NOT hot-deployed to external OXP host. No commit, push, reset, service restart, or user-database mutation.

## Executive engineering decision

Keep one general-purpose edit API. Add optional deterministic **intent selectors** rather than introducing a second general-purpose refactor or edit tool. Reuse the existing shared resolver and the native/OXP transaction machinery. Text editing stays language agnostic; semantic refactoring remains with the existing Refactor capability.

Problem case: `oldString` occurs on lines 78 and 187. A tool can identify both positions but cannot infer whether the agent wants one, a subset, or all of them. The correct interface expresses this choice directly. A zero-configuration unique edit remains the common fast path.

## Implemented selection contract

```ts
type ExactSelection =
  | { mode: "one"; atLine: number }
  | { mode: "selected"; atLines: number[] }
  | { mode: "all"; expectedMatches?: number }
```

All selectors are optional and apply to `oldString`/`newString` exact edits. Mode `one` requires exactly one exact occurrence whose first character is on the requested 1-based line. If more than one occurrence begins on that line, reject rather than pick the first. Mode `selected` checks 1–128 distinct line targets within the same source snapshot before proposing an atomic replacement plan; one invalid target aborts every selected edit. Mode `all` collects all exact matches and, if provided, asserts `expectedMatches` before any write. The legacy `replaceAll:true` form remains supported; contradictory `replaceAll`/selector combinations are refused.

No explicit selection falls back to fuzzy matching or nearest-line guessing. The shared edit engine preserves existing EOL adaptation, BOM handling, permission boundaries, read grounding, revalidation under lock, diff reporting and mutation receipt behavior. It does not treat a failure as a successful no-op.

## Performance finding

Previous matcher `collect()` invoked **all eight matching strategies** even when an exact candidate was already known. The new logic stops after the first eligible nonempty fuzz tier, while still collecting and arbitrating every candidate *inside that tier*. The policy of preferring the lowest-risk tier therefore remains unchanged. `Resolution.all` now contains candidates at the winning tier only; lower-ranked tiers are intentionally not evaluated.

Measured on the development machine with Bun v1.4.3, source generated by `script/bench-edit-ax.ts`, repeated warmups, same file shapes:

| Generated lines | Before, ordinary exact p50 | After, ordinary exact p50 | Improvement |
| ---: | ---: | ---: | ---: |
| 500 | 0.354 ms | 0.049 ms | ~7.2× |
| 5,000 | 2.989 ms | 0.258 ms | ~11.6× |
| 20,000 | 11.718 ms | 1.040 ms | ~11.3× |

20,000-line p95 decreased from 14.149 ms to 2.147 ms. These are **matcher microbenchmarks, not end-to-end agent latency measurements**. They exclude file I/O, permission latency, source formatting, LSP, and the provider's token/roundtrip cost. Environment noise and JIT variability mean more repetitions and production trace sampling are required before treating the ratios as production throughput claims.

Streaming mode for `one`/`selected` now stores only explicitly requested matches plus capped diagnostic line positions. Storage for candidate selection is O(k + C), where k <= 128 requested lines and C is the fixed diagnostics cap, excluding the file's line index and output spans. This avoids allocating one `Match` object per repeated occurrence as formerly done for selection.

## Safety invariants / limitations

1. No match: no mutation. Multiple exact matches without selector: no mutation.
2. Selector line numbers are exact positional constraints, not confidence hints.
3. A match starting on the selected line is necessary, but **line position alone does not establish causal identity** if independent concurrent edits move or replace entire duplicate blocks. Grounded snapshots are preferable, and stale fingerprints must be checked at commit.
4. Explicit all with mismatched expected count: no mutation.
5. A subset must validate in full before the first span is committed. Existing per-file commit owner handles revalidation.
6. Existing refactor and batch `edits:[...]` operations do not automatically inherit per-operation selection; this implementation changes only the exact top-level edit path.
7. No semantic AST identity, persistent match handles, structural scoping, or user-confirmed selector inference is implemented in this slice.
8. No claim of agent-task success-rate improvement without a controlled agent-task evaluation.

## Next architectural phases

### P0: Candidate handles and structured recovery

Return typed `needs_selection`/candidate items rather than requiring agents to parse freeform error strings. Candidate handles should bind canonical root, path, read fingerprint, normalized needle, match span, and selector provenance; their scope is a short-lived resolver cache. Revalidation, path authorization and permissions remain with the existing execution owner. Handle IDs are selectors, never security capabilities. Keep repair output under OXP's 1,024-character tagged-error limit or add an explicitly typed metadata route.

### P0: Batch and patch intent convergence

Extend `edits:[{oldString,newString,...}]` with the same selection vocabulary through the existing `strategy.ts` owner once concurrent edits are reconciled. Patch hunks should take a positional/precondition identity that is independent of fuzzy priority and verified transactionally. Avoid long-lived offset references across unrelated writes. Distinguish atomic multi-file dependencies from the current independent/per-file success policy and preserve rollback ownership.

### P1: Structural selectors without reinventing Refactor

Optional `within:{symbol,kind,signature?}` resolves a structural source span using existing Symbols/Refactor AST services. Keep actual byte mutations in the text engine. Provide duplicate symbol signature disambiguation and scoped all-replacement. Non-parser languages use bounded text anchors. Do not silently choose a model-ranked candidate.

### P1: Immutable snapshot-based optimistic concurrency

Add optional `expectedFileFingerprint` or read revision for source-line selectors. Reject stale selectors even when the same needle still happens to occupy the requested line. For safe, independent changes, selectively rebase only when candidate identity and all preconditions survive re-read. Report `stale`, `ambiguous`, `already_applied` and `conflict` distinctly.

### P1: Cross-tool no-op/overwrite semantics

Harmonize Edit/Write/Patch behavior for creation, full-file replacement, overwrite refusal, BOM and newline preservation, idempotent retry receipts, explicit expected-version writes, and partial-commit truthfulness. Never infer successful application solely because newString appears in a file.

### P1: Real AX and throughput measurement

Build a fixed evaluation corpus with duplicate lines, shared method bodies, same-line occurrences, mixed EOL/BOM, nested scopes, stale commits, editor formatter changes, and maliciously ambiguous inputs. Run the same agent/model/task set against old and new wire contracts. Measure first-attempt correct-edit rate, tools per successful change, token overhead, intent-correct final diff, unsafe edit count, p50/p95 planning and commit latency, and memory allocations. Sample real-world files in addition to synthetic benchmarks.
