Use `apply_patch` for file mutations. This is the GPT-facing name for OpenCode's hardened bulk patch engine. Prefer one complete patch call over several sequential edits when the desired changes are already known.

The tool accepts either the native OpenCode patch format below or a git-style unified diff. `format:"auto"` is the default and detects which one you supplied.

QoL/safety controls:
- `apply:true` is the `apply_patch` default: validate the entire change set, ask once, atomically apply it, and fail without writes if any conflict exists.
- `apply:"if-clean"`: validate first; if there are zero conflicts, ask once and atomically apply it. If conflicts exist, return a compact plan without writing.
- `apply:false`: dry-run only. Validate and return the plan without writing or asking permission.
- `showDiff:true`: include per-file diffs in plan output. Default false keeps plans token-lean.
- The engine checks stale prior reads, merges repeated update sections safely, supports add/update/delete/move, serializes overlapping writes with file locks, and rolls back captured preimages if commit fails.

Native OpenCode patch format:

*** Begin Patch
[ one or more file sections ]
*** End Patch

Within that envelope, you get a sequence of file operations.
You MUST include a header to specify the action you are taking.
Each operation starts with one of three headers:

*** Add File: <path> - create a new file. Every following line is a + line (the initial contents).
*** Delete File: <path> - remove an existing file. Nothing follows.
*** Update File: <path> - patch an existing file in place (optionally with a rename).

Example patch:

```
*** Begin Patch
*** Add File: hello.txt
+Hello world
*** Update File: src/app.py
*** Move to: src/main.py
@@ def greet():
-print("Hi")
+print("Hello, world!")
*** Delete File: obsolete.txt
*** End Patch
```

It is important to remember:

- You must include a header with your intended action (Add/Delete/Update)
- You must prefix new lines with `+` even when creating a new file
