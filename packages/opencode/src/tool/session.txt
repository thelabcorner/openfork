Inspect the user's OpenFork sessions.

This model-facing surface is inspection plus one destructive action. Use task for subordinate agent delegation and Swarm capabilities for durable collaboration. Session creation, prompting, forking, pause/resume, and other Session mutations belong to their owning backend/UI/domain surfaces rather than this inspection tool.

Use one action per call.

Existing-session actions use sessionId as the source of truth. Do not invent or guess a directory for a session.

list discovers sessions by metadata. search recalls sessions by indexed titles/content and exact tool-call evidence. status only reads status. messages only reads existing conversation text. children inspects a whole supervised cohort at once. delete permanently removes one session.

list filters: search, roots, parentId. Use parentId to enumerate the child sessions of one session — subagent/task children appear there, which is how you recover a failed or interrupted task's session id after it scrolled out of context.

search is the preferred cross-session recall surface. It is a bootstrap-free durable index read: it does not open Sessions or hydrate transcripts. query searches bounded indexed conversation projections. tool reads a producer-owned exact tool-call sidecar (exact tool identity + call time + bounded safe input/lineage text), so steady-state tool recall never decodes message/part payloads; combine tool + query to search that bounded input projection. scope defaults to current and may be current, project, or global; roots, parentId, includeArchived, and limit further bound the search. ranking defaults to recent; use ranking:"relevance" for historical/textual research. Results expose epoch and ISO timestamps plus latestAt and explicit timestamp bases. coverage.complete=false means historical projection coverage is incomplete; treat zero hits as "not proven". Set repairIndex:true to advance one small resumable historical projection chunk before retrying. Ordinary search never performs repair or historical payload hydration.

Temporal contract: keep four clocks distinct. retrievedAt/observedAt is when this tool observed state. Session updatedAt is durable Session-record mutation time and can move for metadata/configuration changes, so it is not guaranteed conversation activity or runtime liveness. Message createdAt is conversation event/turn time. search latestAt is the newest matching evidence clock and explicitly states whether it came from conversation evidence or only a Session-record fallback. Prefer newer evidence for current-task reconstruction unless the user asks for history, but never erase older evidence solely because it was superseded.

children is the preferred supervision inspection surface. Prefer it over issuing one status call plus one messages call per worker. It returns one bounded, compact, structured snapshot of every direct child worker of a parent session in a single tool call:

- parentId: defaults to the CURRENT session, so a supervisor normally omits it. Pass it to inspect another session's children.
- groupId: restricts the snapshot to one supervision cohort (the assistant-turn-derived supervision group id). Use it to see exactly the workers you launched together.
- limit: bounded row cap (default 25, hard max 50). When children exceed the cap, the result sets truncated: true.

Each worker entry reports sessionId, mode (foreground | background | supervisor | unknown), agent, description, live status, a conservative blocked classification, and cheap evidence: latest meaningful assistant activity (truncated), last/current tool, pending permission/question signals when available, tokens, cost, updatedAt with ISO/age/basis, and a terminal summary for completed/failed workers. Supervised workers are distinguished from ordinary background/foreground children by mode. Child ordering uses Session-record updatedAt plus a deterministic session-id tie-break; do not infer liveness from updatedAt alone.

children returns a bounded projection, never transcripts. Full transcript inspection remains available through session messages (action "messages", sessionId).

delete permanently removes one session by sessionId, including its messages and history. Deleting a parent recursively deletes its children. The calling session and producer-owned sessions (special-agent transcripts, scheduled-task runs, delegated workers) are refused. Prefer deleting idle sessions; deletion cannot be undone.

oxp lists ChatGPT/OXP parent activities (conversations) as compact rows with call counts, plane mix, and dated last-seen metadata, or returns one activity's recent invocations when oxpActivityId is set. Results include retrieval time plus ISO/age/time-basis fields. lastSeenAt means latest observed OXP activity, not proof that a worker/runtime is still live. Activity ids are opaque; titles are display metadata only. The read is process-global and bootstrap-free: it needs no sessionId, scope, or directory. Invocation args/results are never returned.

messages may wait for an already-running Session to become idle before reading when the next step genuinely requires the completed transcript. Waiting never starts, resumes, or otherwise mutates execution. Returned messages are explicitly oldest-to-newest and carry event-time ISO/age fields plus a retrieval-time window anchor; later messages normally supersede earlier mutable-state claims, while live code/runtime remains the source of current truth.

Dreamer-specific read safeguards: Dreamer cannot use live status, list withStatus (which would fan out live worker inspection), messages wait, or index repair. Historical get/messages deliberately report status unobserved and avoid per-directory live status initialization. Dreamer's discovery list/search result limit is 20. Dreamer's messages limits are 12 returned messages, a 200-row fallback scan, 6,000 serialized UTF-8 bytes per text and 24,000 serialized UTF-8 bytes in total, preserving newer evidence first and clearly reporting excerpts/omissions. A request above these caps reports limitCapped even when there are fewer actual records, rather than claiming omitted historical records without evidence. These are bounded read/output ceilings; message decoding can still cost work proportional to the selected text. Normal callers retain their existing semantics.
