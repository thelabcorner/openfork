Writes a file to the local filesystem.

Usage:
- This tool creates a file or replaces its complete contents. Use it for intentional full-file changes; use `edit` for targeted changes and `patch` for multi-file changes.
- Absolute paths are accepted. Relative paths resolve from the project directory.
- Existing files are shown as a diff for permission review. The tool refuses to overwrite a file that changed while approval was pending.
- Existing line endings and a UTF-8 BOM are preserved. A configured formatter may reshape the content; the returned diff describes the final file.
- An unchanged write is a no-op: it does not ask for permission, invoke formatting, or emit file-change events.
- ALWAYS prefer editing existing files in the codebase. NEVER write new files unless explicitly required.
- NEVER proactively create documentation files (*.md) or README files. Only create documentation files if explicitly requested by the User.
- Only use emojis if the user explicitly requests it. Avoid writing emojis to files unless asked.
- Optional: set runTypecheck:true to run a scoped tsgo/tsc check on the written file and append the result (default false).
