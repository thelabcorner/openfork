Edit files — single precise changes AND bulk multi-file/multi-hunk changes in ONE tool. Pick the pathway BEFORE calling.

COST MODEL: every tool call reprocesses the full context window, so n sequential edit calls cost ~n times the input tokens of ONE bulk call carrying the same n edits. Single precise edits cost nothing extra — but the moment you know 2+ edits upfront, BATCH THEM. Bulk calls apply in ONE call when every hunk validates cleanly (apply defaults to "if-clean"); only conflicted patches cost a second round trip.

ROUTING — how many locations do you already know?
- ONE file, ONE contiguous hunk, no create/delete/rename -> single-edit params. Applies immediately.
- 2+ files; 2+ hunks in one file; any create/delete/rename/move; a refactor spanning locations -> patchText. Collect reads/greps first, then emit ONE patchText call.
- patchText MUST NOT be combined with single-edit params. A single brand-new file with no other changes -> `write`.

SINGLE-EDIT PATHWAY (filePath, plus exactly one of):
- oldString/newString: exact replacement; safest for small blocks. replaceAll:true renames every occurrence (exact matches only).
- line + oldText + newText: replace line N. oldText is REQUIRED and must be text currently on that line.
- startLine + endLine + newText (+ oldText): replace a range. Ranges over 5 lines require oldText whose first and last lines match the range's endpoints. Add delete:true (no newText) to REMOVE the range.
- insertAt + newText: insert after line N. insertAt:0 prepends. Any N>0 requires oldText confirming line N.
- appendFile:true + newText: append at EOF.
- nearText + oldText + newText (+ occurrence): replace oldText within ±5 lines of a unique anchor.
- edits:[...]: single-file atomic batch of the above shapes. Every op is validated against the file as read, overlaps are rejected, and ops apply against original coordinates so earlier edits never shift later targets.

RULES
- You MUST Read the file first; edits to files that changed after they were read are rejected, and line-targeted edits to unread files carry a warning. Re-read on either signal.
- Preserve exact indentation as it appears AFTER the `N: ` read prefix; never include the prefix (it is stripped with a warning if detected).
- Ambiguous targets are REFUSED, never guessed: if text matches more than one location the error lists every candidate line number. Add context, or use replaceAll for a deliberate rename.
- If a match is resolved by anything other than exact text, the result says so — send exact text next time.
- A no-op returns applied=0 without writing. applied reflects the TRUE number of changes.
- If the formatter reshapes the file after your edit, the result says so; re-read before further line-targeted edits.
- runTypecheck:true runs a scoped tsgo/tsc check (single-edit pathway only).
- AVOID emojis unless explicitly requested.

BULK PATHWAY (patchText + optional apply/format/showDiff)
- apply defaults to "if-clean": validate everything, then apply in the same call if there are zero conflicts, or return a plan and write nothing if there are any. apply:false forces a plan; apply:true forces application.
- EVERY hunk is validated BEFORE ANY write, hunks are positioned by unique content match (an ambiguous hunk is refused with candidate line numbers, not applied to the first match), and the write loop unwinds completely on failure — never a half-applied refactor.
- Repeated `*** Update File:` sections for one path are merged; contradictory operations on one path are reported as conflicts, never silently dropped.
- Two formats, auto-detected (pass format to force): the opencode format (*** Begin Patch / *** Add File: / *** Update File: + @@ hunks / *** Move to: / *** Delete File: / *** End Patch), or a git-style unified diff pasted directly.
- Every hunk needs at least one context or removed line; a hunk of pure additions has no determinable position and is refused (use insertAt/appendFile instead).
