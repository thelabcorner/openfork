Bulk mutation tool. PREFER this when 2+ files or arbitrary multi-hunk changes are already known, or when creating/deleting/moving files. Put the complete change set in ONE patch call instead of issuing sequential edit calls. For 2+ simple non-overlapping edits in one file, `edit` with `edits:[...]` is the lighter pathway when available. Use single-edit params only for one known hunk.

Use paths relative to the project directory. `format` selects the patch syntax (`auto`, `opencode`, or `git`); formatting of changed files follows the configured formatter. `Add File` requires a missing target, unless the target already has identical content (an idempotent no-op); use `Update File` to change an existing file. A move fails safely if its destination already exists. Every content line needs its patch prefix: `+` for additions, `-` for removals, and a leading space for context. To delete a file with a git diff, include hunks that account for its complete current contents; native `*** Delete File:` is an explicit path-only deletion.

The tool validates all hunks before asking permission and rechecks every source and destination after approval. If a file changed while approval was pending, nothing is written; re-read it and submit a fresh patch. If a write fails partway through, it attempts to restore files it can still verify it owns.
